# Dummy 机械臂真机标定、D435 测试与 200 Hz 联调指南

本文给出当前仓库从“接口已能编译、参数尚未真机确认”到“允许单关节低速闭环”的执行顺序。范围仅包括六轴机械臂、节点 7 夹爪、单台腕部 RealSense D435、Linux 上位机与 STM32 固件；不包括训练和推理。

文中的角度维护命令使用 **度**，二进制上位机接口使用 **弧度**，夹爪二进制接口使用 `[0, 1]`，其中 `0` 表示张开、`1` 表示闭合。

> 安全边界：这不是机械安全认证文件。急停、驱动器断电、制动、支撑工装和允许电流必须以实机电气图、驱动器手册和机械设计为准。`!STOP` 只是软件保持，`!DISABLE` 会撤销电机保持力，均不能替代硬件急停。

## 1. 总体顺序和放行门

必须按以下顺序执行；任何一级失败都回到该级修正，不得带病进入下一级。

| 阶段 | 内容 | 成功后允许做什么 |
|---|---|---|
| G0 | 台架、急停、支撑、版本和接线确认 | 给主控和驱动器上电，但不运动 |
| G1 | 六个关节的正方向和反馈方向 | 进入零点标定 |
| G2 | 可复现参考姿态与零点 | 测减速比 |
| G3 | 六轴减速比和回差 | 探索安全工作区 |
| G4 | 机械边界、线缆边界、软件限位 | 测试夹爪 |
| G5 | 夹爪方向、开闭端、归一化映射 | 独立运行 D435 |
| G6 | D435 枚举、稳定性、时间戳和标定版本 | 固化统一配置 |
| G7 | YAML、固件参数、配置哈希完全一致 | 开发并台架验证 200 Hz 执行器 |
| G8 | 200 Hz latest-wins、TTL、租约、HOLD 通过台架测试 | 单关节低速上电联调 |
| G9 | 六轴逐关节低速联调通过 | 才能考虑多关节、采集或更高层功能 |

当前代码的安全门保持为：

```yaml
hardware_parameters_verified: false
```

固件 `firmware_interface` 分支中的门保持为：

```cpp
kHardwareParametersVerified = false;
kExternalTargetExecutionReady = false;
```

在 G1～G6 的书面记录完整、G7 配置哈希匹配、G8 执行链完成前，不得把这些门改为 `true`，也不得在真机上使用 `allow_unverified_hardware=True` 绕过门禁。

## 2. 是否需要在 Keil 里打断点

真机运动调试不以 Keil 断点为主要手段。断点会停止 MCU 程序；如果电机板仍保持最后一个 CAN 目标，机械臂可能继续保持、下坠或出现通信超时后的未知行为。

推荐分工如下：

| 场景 | Keil 断点 | 推荐方法 |
|---|---:|---|
| 解析命令、数组越界、状态机逻辑，电机总线断开 | 可以 | 单步、Watch、PC 单元测试 |
| 检查 200 Hz 周期耗时 | 不要在周期内停住 | GPIO 翻转配合示波器/逻辑分析仪，或 DWT 计数器 |
| 关节正方向、零点、减速比、限位 | 不建议 | USB 日志、`#GETJPOS`、量角工具、录像、低速小步运动 |
| 看门狗、TTL、拔线进入 HOLD | 不建议 | 记录状态帧、CAN 报文和 GPIO 时间 |
| 真机已使能且承重 | 禁止随意暂停 | 先 HOLD、机械支撑、切驱动电源，再连接调试器 |

若必须断点：先卸载末端负载，用工装承托 J2/J3，令系统进入 HOLD，断开或禁止电机功率级，再在不会发出运动目标的代码路径中暂停。Keil 官方说明也明确指出，执行到断点时程序会停止；因此断点适合查逻辑，不适合作为运动安全手段。

## 3. G0：上电前准备

### 3.1 人员和器材

首次联调至少两人：一人操作 Linux/串口，另一人始终站在机械臂运动包络外并控制硬件急停。准备：

- 可直接切断驱动器功率、但不切断上位机记录能力的硬件急停；
- 能承托 J2/J3 的吊带、支架或配重，断电后机械臂不得自由跌落；
- 无负载、无尖锐工具的末端；
- 量角器或数字倾角仪，最好再有百分表/激光标线；
- 关节轴线和正方向贴纸、细头记号笔；
- D435 原装或可靠 USB 3.x 线缆，优先直连主机端口；
- 能记录屏幕、机械臂全景和关节局部的相机。

每次上电前记录：


### 3.3 静态检查

逐项确认：

1. CAN 节点 1～6 与 J1～J6 一一对应，节点 7 是夹爪；标签同时贴在线束和驱动板两端。
2. D435 线缆随 J4/J5/J6 转动时不会被夹住、拉紧或缠绕。
3. 特别确认 J6 是否存在滑环。没有滑环或线束没有做多圈设计时，当前固件的 `±720°` 绝不能直接视为可用范围。
4. 关节周围没有人手、工具和松动物体；机械臂基座固定。
5. J2/J3 已承托。按下急停后，确认驱动功率确实被切断，且支撑能承受机械臂重量。
6. USB CDC 和 D435 尽量位于不同的主机 USB 控制器，不通过无源 Hub。

G0 放行条件：硬件急停实测有效、断电不坠落、节点映射无歧义、当前版本均已记录。

## 4. 维护串口的统一用法

G1～G5 使用主控 USB CDC 的 ASCII 维护接口，不启动 Python 二进制控制客户端。关闭所有可能占用 `/dev/ttyACM0` 的程序，然后：

```bash
python -m serial.tools.miniterm /dev/ttyACM0 115200 --eol LF
```

USB CDC 的波特率通常只是终端参数，但仍统一写为 `115200` 便于记录。每条命令以 CR 或 LF 结束。

常用命令：

```text
#GETJPOS                         读六关节应用角，单位度
#CMDMODE 2                       可中断目标点模式
!START                           使能六轴
!STOP                            软件停止/保持，不是硬急停
!DISABLE                         撤销六轴使能；J2/J3 未支撑时禁止使用
>j1,j2,j3,j4,j5,j6,speed         六轴绝对角目标，单位度
#OFFSET_J node                   把该电机板当前位置写为电机零位
#REBOOT node                     重启节点 1～7 中的一个
```

每次只改变一个关节，其他五个目标必须复制刚刚由 `#GETJPOS` 读到的值。命令最后的 `speed` 先使用 `2～5` 的保守值；它是旧固件速度尺度，不等同于上位机 YAML 中的 `rad/s`。

当前 `!START` 会使能全部六轴，不是单轴使能；`!STOP` 会请求保持当前位置并把软件 `isEnabled` 置为假，但不会切断六个电机驱动；`!DISABLE` 才会撤销全部六轴使能。正式 G1 前推荐在 `firmware_interface` 增加带节点校验的单轴使能/失能维护命令。该功能未完成时，只能在其余关节也已可靠支撑、当前六轴目标稳定且第二名操作员掌握硬急停的条件下做单轴“小运动”测试，不能称为电气隔离的单轴测试。

`#ACC_J`、`#SPEED_J`、`#I_LIMIT_J` 会要求电机板保存设置；当前又缺少对应的只读查询命令。使用前应先补齐参数读回、备份和恢复路径，禁止为了“更安全”盲目写一个未经电机/机构核算的数值。

以下命令当前禁止在整机上直接执行：

- `!HOME`、`!RESET`：会自动运动多个关节；参数尚未验证。
- `!CALIBRATION`：当前实现注释要求人工摆 L 姿态，但函数中没有等待人工确认，会继续两次写入零点并自动运动。
- `!HAND_ZERO`：当前实现按固定 `900 ms` 向两端运动，没有端点开关、堵转判定或电流停止条件。
- `#OFFSET_J 0`：维护接口只应使用明确的节点 1～7，禁止尝试广播写零点。

## 5. G1：逐关节确认真机正方向

### 5.1 正方向的唯一标准

以 URDF 的右手定则为准，不以“电机顺时针”或“肉眼看起来向前”为准。当前 URDF 轴为：

| 关节 | 父坐标系中的轴 | 正方向判断 |
|---|---|---|
| J1 | `+Z` | 右手拇指指向 `+Z`，四指弯曲方向为正 |
| J2 | `+X` | 右手拇指指向 `+X` |
| J3 | `+X` | 右手拇指指向 `+X` |
| J4 | `+Y` | 右手拇指指向 `+Y` |
| J5 | `+X` | 右手拇指指向 `+X` |
| J6 | `+Y` | 右手拇指指向 `+Y` |

在每个关节外壳上贴 `+` 箭头，并拍下同时能看到父连杆、轴线和箭头的照片。若 URDF 轴与装配坐标不一致，先改 URDF/坐标定义并评审，不能靠口头约定。

### 5.2 单关节动作流程

对 J1、J4、J5、J6，先试 `+0.5°`；对承重且接近边界的 J2/J3，先用远离当前边界的方向试 `0.2°`。当前默认参考姿态中 J2 约为 `-73°`、J3 约为 `180°`，因此第一次通常只能让 J2 增大、J3 减小。

每个关节都执行：

1. 支撑承重关节，确认急停操作员就位。
2. 发送 `#GETJPOS`，把六个数抄为 `q0`；若读数跳变或超出当前软件范围，停止。
3. 发送 `#CMDMODE 2`，再发送 `!START`。
4. 只给待测关节构造 `q1 = q0 ± 0.2°/0.5°`，发送完整六轴目标。例如当前读数为 `0,-73,180,0,0,0`，测试 J1 正向：

   ```text
   >0.5,-73,180,0,0,0,3
   ```

5. 观察机械方向，同时连续读两次 `#GETJPOS`。位姿方向和反馈增减必须都与 URDF 相符。
6. 发送原始 `q0` 返回；确认停止后发送 `!STOP`。
7. 只有机械支撑已经接管负载时才发送 `!DISABLE`。
8. 相同方向重复三次，再从相反方向重复三次，以排除回差造成的误判。

### 5.3 记录和修正

| 关节 | 命令变化 | 实际物理方向 | 反馈变化 | URDF 一致 | 重复 3 次 | 结论 |
|---|---:|---|---:|---:|---:|---|
| J1 | | | | | | |
| J2 | | | | | | |
| J3 | | | | | | |
| J4 | | | | | | |
| J5 | | | | | | |
| J6 | | | | | | |

当前固件构造参数中的 `inverseDirection` 初值为 J1/J3/J5/J6=`true`，J2/J4=`false`。这只是旧代码初值，不是标定结论。

若方向错误，应在 `firmware_interface` 分支中统一修改固件的方向定义，使“命令正、反馈正、URDF 正”三者一致，然后重新编译、刷写并完整重测该关节。不要只修改 YAML：当前 Python 代码仅校验 `joint_sign`，尚未用它做运行时角度变换；两层各翻一次符号还会制造双重反向风险。

G1 放行条件：六个关节的正负小步运动均与 URDF 一致，反馈符号一致，重复测试无偶发反向或其他轴联动。

## 6. G2：建立可复现零点

### 6.1 先统一“零点”和“参考姿态”

当前固件不是把所有电机板零位解释为应用角 `0°`。其关系是：

```text
应用关节角 = 电机板角度（已含 inverseDirection） + initPose
```

上电后 `initPose` 是：

```text
REST_POSE = [0, -73, 180, 0, 0, 0]°
```

因此，若在当前位置直接执行 `#OFFSET_J 2`，随后 J2 的应用读数应接近 `-73°`，不是 `0°`；J3 同理应接近 `180°`。这也是为什么不能把六轴摆成视觉上的“全零”后一次性写零点。

本项目建议先把可重复机械参考姿态定义为 `q_ref`，第一版可沿用 `REST_POSE`，但必须为每个关节建立：

- 定位销、靠块或可重复贴合的基准面；
- 正视和侧视照片；
- 倾角仪/量角器读数；
- 允许误差；
- 到达基准时必须从哪个方向接近，以消除回差。

### 6.2 推荐的零点写入流程

不要执行 `!CALIBRATION`。逐节点执行：

1. 断开运动命令源，机械支撑到位。
2. 若机构可安全手动回驱，则在电机失能且受支撑时慢慢对齐 `q_ref` 工装；不可回驱时，只能用 G1 已验证的方向，以 `0.2°` 小步低速接近。
3. 最后一次必须从记录中规定的同一方向靠近基准。
4. 复核相邻连杆基准、量角工具和照片，第二人签字。
5. 只对当前节点发送 `#OFFSET_J node`。该命令可能把偏置持久化到电机板，发出前再次口头确认节点号。
6. 等待应答后发送 `#REBOOT node`，等待节点重新上线。
7. 发送 `#GETJPOS`，期望值是 `q_ref` 对应的应用角；允许误差按工装精度制定，首轮建议先以 `≤0.5°` 作为工程门槛，而不是安全额定值。
8. 从正、负两个方向分别离开 1° 再回到参考姿态，各重复三次，记录重复性和回差。
9. 一个节点通过后才做下一个节点。

### 6.3 必须修正的结构性问题

正式上线前应在 `firmware_interface` 分支把以下三项变成同一份生成配置，不再依赖硬编码：

- `q_ref/initPose`；
- 六轴 `inverseDirection`；
- 六轴减速比和软件限位。

YAML 中的 `joint_zero_offset_rad` 当前也只是元数据，未参与 Python 运行时换算。选择一种唯一架构：推荐让固件对外直接提供 URDF 坐标系中的绝对关节角，上位机不再做符号和零点二次变换；YAML 只记录和校验这些物理参数。

G2 放行条件：每个关节可从断电/重启后恢复到一致的 `q_ref` 读数；零点误差、重复性和回差均有记录；整机自动 `!CALIBRATION` 仍保持禁用。

## 7. G3：验证减速比与回差

固件当前减速比初值为：

| J1 | J2 | J3 | J4 | J5 | J6 |
|---:|---:|---:|---:|---:|---:|
| 30 | 30 | 30 | 24 | 30 | 50 |

这里的含义是“电机转数 / 输出关节转数”。固件换算为：

```text
motor_turns = commanded_joint_deg / 360 × reduction
```

### 7.1 测量方法

1. 选择远离机械边界和自碰撞的位置；J2/J3 保持支撑。
2. 在输出连杆安装量角工具，不要只测电机轴。
3. 从同一方向消除回差后，把该位置记为 `A`。
4. J1/J4/J5/J6 先命令 `10°` 位移；J2/J3 先命令 `5°` 位移。若空间不足就减半，但测量分辨率也必须相应提高。
5. 等待反馈稳定，记录命令变化 `Δq_cmd` 和实际输出变化 `Δq_meas`。
6. 用下式估算实际减速比：

   ```text
   reduction_new = reduction_config × Δq_cmd / Δq_meas
   ```

7. 在三个不同中间位置重复，并分别测正向和反向。不要用撞硬限位的方法消除回差。
8. 正反向结果的差主要反映回差/弹性，不能通过修改减速比掩盖。

### 7.2 判定

首轮工程建议值：平均比例误差不超过 `1%`，相同方向重复性不超过 `0.5°`。若任务精度、量具精度或机械设计另有要求，以更严格且经评审的指标为准。

若超差：先检查量具装法、关节是否达到目标、电机是否丢步、联轴器是否松动，再决定是否修改减速比。修改应落在 `firmware_interface` 分支，并同步生成到 YAML 元数据和配置哈希；刷写后重做 G2 和 G3。

G3 放行条件：六轴均有至少三位置、双方向记录，比例误差和回差已分开评估，没有丢步或联轴器滑移。

## 8. G4：建立真实限位

当前固件/YAML 中的范围只是待验证初值：

| 关节 | 当前最小值 | 当前最大值 | 特别风险 |
|---|---:|---:|---|
| J1 | -170° | 170° | 基座线束 |
| J2 | -73° | 90° | 重力下坠、底座碰撞 |
| J3 | 35° | 180° | 重力下坠、肘部碰撞 |
| J4 | -180° | 180° | 腕部线束 |
| J5 | -120° | 120° | 自碰撞、D435 碰撞 |
| J6 | -720° | 720° | D435/夹爪线束扭断；无滑环时尤其危险 |

### 8.1 先找物理安全边界，不碰硬止挡

1. 断电、支撑后手动检查关节全程的外壳间隙和线缆余量；不能安全回驱的轴只做目视和 CAD 检查。
2. 在疑似边界内侧至少保留 `5～10°` 初始裕量；线缆、夹点和人体可达区需要更大裕量。
3. 上电后从中间安全位置出发，以 `0.5°` 小步、速度尺度 `2～3` 靠近，任何线缆拉紧、摩擦、异响、电流突增或结构接近都立即停止。
4. 记录最后一个确定安全的位置，退回至少 2°，再从同一方向复测三次。
5. 另一侧同样测试。J6 必须以线缆允许扭转圈数为准，不得照抄 `±720°`。

### 8.2 软件限位的双层验证

取：

```text
软件最小值 = 实测安全最小值 + 安全裕量
软件最大值 = 实测安全最大值 - 安全裕量
```

把值同时写入：

- 上位机 `configs/robot_config.yaml` 的 `joint_limit_min_rad/max_rad`；
- 固件生成配置和实际 `MoveJ` 检查使用的限位。

验证每个关节：

1. 边界内 `1°` 的目标可以低速到达；
2. 恰在边界的目标行为符合约定；
3. 边界外 `0.1°` 的目标被上位机和固件分别拒绝，机械臂不动；
4. NaN、Inf、少字段和错误单位被拒绝；
5. 拒绝后仍处于 HOLD 或之前的安全目标，不出现跳变。

G4 放行条件：六轴机械、线缆、自碰撞边界均已测量；双层软件限位生效；J6 范围有明确的滑环/线束依据。

## 9. G5：夹爪映射

### 9.1 当前实现的风险

节点 7 当前初值为减速比 `8`、电机角范围 `-115～115°`，归一化定义为：

```text
target_angle = openedAngle + percent/100 × (closedAngle - openedAngle)
```

`!HAND_ZERO` 会向打开端运动 `900 ms`、立即写零点，再向闭合端运动 `900 ms`；没有行程开关或堵转/电流停止条件。现阶段禁止直接运行。

在进入夹爪实测前，先在 `firmware_interface` 分支增加至少一种安全终止条件：可靠的端点开关，或经电机/机构验证的电流阈值 + 速度/位置停滞判定 + 最大时间 + 最大行程。任一条件触发都要先清零电流目标，再报告结果。

### 9.2 改造后的标定流程

1. 空夹爪测试，不放工件，手指和工具离开夹持区。
2. 从驱动器/电机额定值和机构允许力推导低电流初值；不要直接把协议上限 `2.0 A` 当成安全值。
3. 使能节点 7，向打开方向短脉冲点动；每个脉冲后电流必须回零。确认 `!HAND_O` 的物理含义确实是打开，`!HAND_C` 是闭合。
4. 以安全终止条件寻找机械全开端，向内退一个机械裕量，记录 `openedAngle` 和两指总开口毫米值。
5. 同样寻找全闭端；若手指会硬碰，闭合标定点应在硬碰前留裕量。记录 `closedAngle`。
6. 增加只读维护命令（例如 `#GET_HAND`），应返回节点 7 原始角、归一化位置、电流、使能和标定状态；当前 ASCII 接口缺少这个必要读回命令。
7. 测试 `0%、25%、50%、75%、100%`，每点从打开和闭合两侧各到达三次，测量实际开口毫米值。
8. 确认二进制状态的夹爪反馈单调、被限制在 `[0,1]`，且 `0=开、1=闭`。
9. 用软质测试块做低力夹持，测试块不得是手指，不得在夹爪下方放易碎物。

若在修改前为了验证方向而使用现有 `!HAND_O/!HAND_C`，必须在机械台架上、从经计算的低电流开始，并由脚本产生有界短脉冲后立即发送 `!HAND_DIS`；禁止人工输入连续电流命令后等待观察。

G5 放行条件：夹爪端点检测不是固定时间猜测；方向、最大行程、电流限制、毫米开口和 `[0,1]` 映射都有双向重复数据。

### 10.3 图像和深度检查

1. 彩色图无严重过曝、频闪、拖影；深度单位可从 SDK 查询并记录。
2. 对齐后的深度与彩色物体边界方向一致。RealSense 的 `align` 是运行时重投影，不等于相机到腕部的手眼标定。
3. 在工作距离内放置平面靶标，比较中心和四角深度的空洞率、均值和抖动。
4. 让 J4/J5/J6 在 G4 安全范围内手动摆到代表姿态，确认线缆不拉扯、画面不间歇掉线。
5. 同时打开 USB CDC 的只读状态流，确认 D435 满带宽工作时控制状态仍稳定。

先用自动曝光确定工位照明是否稳定；用于数据采集前再固定经实测的彩色曝光、白平衡和深度曝光，并写入 YAML。不要照抄其他相机或其他照明的数值。

### 10.4 标定版本

SDK 会提供设备内参以及设备内部流之间的外参；仍需单独测量 D435 到腕部/末端坐标系的刚体变换。要求：

- 相机安装完成后再做，固定螺钉做防松标记；
- 使用标定板采集覆盖工作空间、距离和姿态的多组图像；
- 保存内参、畸变、深度尺度、`T_wrist_camera`、残差、样本列表和脚本提交号；
- 任何相机拆装、支架变形、分辨率/裁剪模型变化都生成新的 `calibration_version`；
- YAML 中不再使用 `uncalibrated-v0`。

G6 放行条件：序列号固定；30 分钟无不可恢复断流；时间戳和同步阈值满足；工作距离的深度质量有量化记录；手眼标定文件有唯一版本。

### 11.2 在 `firmware_interface` 分支更新

切换分支前保证当前改动已提交，不要把两个分支的修改混在一个工作区状态中：

`firmware_interface` 分支本身不包含 `Upper/dummy-host`，所以切换后不能假定 YAML 仍在工作树。必须提供一个由指定 Git 提交读取 YAML、自动生成 `robot_config_generated.hpp` 的工具；例如让工具接收 `--source-ref upper_computer --source-path Upper/dummy-host/configs/robot_config.yaml`，内部用只读的 Git 对象内容计算规范化哈希。也可使用两个 Git worktree，把固件生成器的 `--config` 指向已提交的上位机 worktree。无论哪种方式，生成文件必须同时记录源提交号。

目前仓库中的头文件是手工生成结果，正式标定不应继续手抄哈希。生成结果至少包含：

- `config_version` 和完整 SHA-256；
- 六轴参考姿态、方向、减速比、限位、速度/加速度；
- `kHardwareParametersVerified`；
- 独立的 `kExternalTargetExecutionReady`。

实际交叉编译目录可按本机工具链调整，但必须保存编译器版本、ELF/HEX 哈希和测试输出。

## 12. G8：接入 200 Hz 目标执行

当前 `firmware_interface` 只完成二进制协议、会话、只读状态和安全门，尚未把外部目标接入实际电机执行。因此必须先在该分支完成以下实现，不能简单把 `kExternalTargetExecutionReady` 改为 `true`。

### 12.1 固件执行结构

推荐数据流：

```text
USB 接收/解码线程
  -> 校验 CRC、版本、会话、序号、NaN/Inf、限位、TTL
  -> 原子发布“最新一个目标”
  -> 立即 ACK

200 Hz 控制任务（每 5 ms）
  -> 读取目标快照
  -> 检查 TTL、租约、故障、控制模式
  -> 应用速度/加速度限制
  -> 一次性完成 rad 到固件关节坐标的转换
  -> 下发电机目标
  -> 只有真正采用后更新 last_applied_sequence
```

要求：

- latest-wins 单槽/双缓冲，不使用会积压旧轨迹点的长 FIFO；
- USB 线程不直接阻塞等待电机运动；
- 200 Hz 读取完整一致的目标快照，不能读到一半新一半旧；
- `target_ttl_ms=100` 到期立即进入 HOLD；
- `lease_timeout_ms=500` 到期撤销租约并进入 HOLD；
- HOLD 的电机行为必须明确：保持当前位置、受控制动或禁能应按轴和硬件能力定义，不能把三种行为混为一谈；
- ASCII 维护控制与二进制控制互斥；获取二进制租约后，运动类 ASCII 命令必须被拒绝；
- 急停、故障、解析失败、USB 断开都不会继续采用新目标；
- 状态帧区分 `last_received_sequence` 和 `last_applied_sequence`。

### 12.2 先在无电机台架验证

至少增加并通过以下测试：

- 新序号覆盖旧目标，旧序号被拒绝；
- 输入 NaN、Inf、越界、错误长度、错误哈希均不产生电机调用；
- 目标超过 100 ms 未刷新进入 HOLD；
- 心跳停止超过 500 ms 撤销租约；
- USB 拔线进入 HOLD；
- 在目标发布并发点反复运行，目标快照无撕裂；
- 200 Hz 周期在最坏负载下不超 5 ms，统计 min/mean/p99/max；
- `last_applied_sequence` 只在控制周期真正采用目标后变化；
- ASCII/binary 所有权互斥；
- 重启默认处于无租约 HOLD，不自动恢复旧目标。

用 GPIO 翻转测周期：任务入口置高、退出置低，用示波器看周期和执行宽度。这里不要在 200 Hz 任务内打断点。

G8 放行条件：无电机台架和协议测试全部通过，拔线/超时行为实测；代码评审完成后才设置 `kExternalTargetExecutionReady=true`，重新生成配置哈希相关文件、构建并刷写。

## 13. G9：单关节低速闭环联调

### 13.1 先补专用联调程序

不要用交互式 Python 一次发送一个目标。TTL 是 100 ms，租约是 500 ms，人工键入无法稳定满足时序。先在 `upper_computer` 分支实现 `dummy-host-joint-bringup`，至少具有：

- 参数：串口、关节号、位移度数、速度、持续时间；
- 默认只允许一个关节变化，其他轴锁定为首次状态；
- 默认位移 `0.2°`，绝对上限由程序限制为一个保守的小值；
- 20 Hz 发送目标，独立且及时发送心跳；
- 键盘/按钮 dead-man，松开立即 HOLD；
- Ctrl-C、异常、串口断开和正常退出都在 `finally` 中请求 HOLD、释放租约、关闭串口；
- 每周期记录 requested、safety-filtered、received sequence、applied sequence、状态年龄、故障位和周期抖动；
- `--dry-run` 不申请真机控制权，只输出将发送的目标；
- 不提供 `allow_unverified_hardware` 的真机快捷入口。

### 13.2 实机顺序

每个关节按 J6、J5、J4、J1、J3、J2 的建议顺序测试；把承重最大的 J2/J3 放最后。每轴：

1. 卸载末端负载，其他轴处于已验证的安全姿态，J2/J3 有支撑。
2. `dummy-host-diagnose` 只读运行 2 分钟，确认状态年龄、哈希、故障和反馈稳定。
3. 用 `--dry-run` 检查关节号、方向、弧度/角度换算和被固定的其他六个动作量。
4. 急停操作员复诵关节号和期望物理方向。
5. 第一次位移 `0.2°`、速度上限建议先从 `0.02 rad/s` 量级开始；具体值受机构和驱动器能力约束，只能向更保守方向调整。
6. 按住 dead-man 运行 1 秒，松开并确认进入 HOLD。比较 requested、applied 和反馈方向。
7. 返回起点。正负方向各三次；再逐步试 `0.5°`、`1°`，每级都重新确认间隙。
8. 测试软件超时：在安全姿态下终止发送进程，确认 100 ms 目标 TTL 后 HOLD；再测试心跳/租约超时。
9. 测试 USB 拔线：只在最小位移、充分支撑下进行，测量从最后有效包到 HOLD 的时间。
10. 连续低速往返 30 次，检查温升、丢步、回差、序号、周期抖动和其他轴是否漂移。
11. 当前轴记录签字后才测试下一轴。

## 14. 任何阶段的立即停止条件

出现以下任一情况立即松开 dead-man/请求 HOLD；若运动未立即停止，按硬件急停：

- 实际方向与口头预期不一致；
- 非测试关节发生可见运动；
- 反馈跳变、NaN、冻结或与物理运动反向；
- 电机异响、丢步、抖动、异常温升或焦味；
- 线缆拉紧、摩擦、夹住或 D435 掉线；
- 机械臂接近人、台面、自身或未记录障碍物；
- 状态年龄超过上限、序号不前进、故障位非零；
- 控制程序退出后仍继续运动；
- 操作者和急停人员对当前状态理解不一致。

停止后不要立即重试。保存终端日志、状态帧、CAN/GPIO 波形和视频，记录最后一个安全版本及复现条件；先在无电机台架解释原因，再恢复真机。
